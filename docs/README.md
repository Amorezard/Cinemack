# Cinemack (Movie Buff v8): how it works, how to run it, where things stand

Updated 11 Nov 2026 (round 27). The root `README.md` keeps the history of v3-v7; this file describes the system as it
is now. Merrimack College student research project; non-commercial.

## 1. What it is
Cinemack answers questions about films and TV (identify a half-remembered film, facts, reception, box office, "what
should I watch"), and is a website around that chatbot: Home rows, Pick Tonight, a release calendar, a watchlist with
TV progress, a profile with imports, friends and privacy controls.

- **Answer path**: question -> planner (the `movie-buff` model in Ollama) -> retrieval over films and Wikipedia
  (`retrieve.py`, `movies.db`, `wiki.db`) + facts in SQL (`tools.py`, `facts.db`) -> answer model streamed to the page.
  Every feature on this path sits behind a switch and was tested with a rule written before its result (section 5).
- **Website**: FastAPI (`web/server.py`, `web/v8routes.py`, `web/v8extra.py`) + a no-build front end in `web/v8/`
  (one ES module per page). `/` is the v8 site (`V8_HOME=1`, round 27); the old page is at `/classic`.
- **Data**: TMDB, Wikipedia, Wikidata, IMDb datasets, MovieLens, OMDb, Guardian, NYT (metadata only), YouTube,
  Netflix engagement reports, TVmaze (website only). Licences and credits: `web/about.html` (generated by
  `python v7_data.py register` from `v7_data.SOURCES`).

## 3. Running it
```bash
source ~/venvs/movie-rag/bin/activate
bash start_site.sh                         # live site on :49151 with v7_lock.env + v8_lock.env + site.env
PORT=49152 bash start_site.sh              # a test copy next to it
bash nightly.sh --dry                      # what the nightly update would do (cron 04:17)
python -m unittest tests.test_v8_r27       # each tests/test_*.py file separately (they set env per file)
```
Laptop workflow: `server-latest\sync.cmd` copies `todo.sh` + `outbox\*` to the server, runs `todo.sh`, brings back
`todo_out.txt` and `sync_out.tgz` (unpacked into `sync\`). Keys live in `~/.movie-buff.env` and `keys.env`
(chmod 600, git-ignored); scripts source them and never print them.

Local front-end checks (no GPU): build the fixture (`tools/make_demo.py`, `make_demo2.py`, `make_demo_tv.py`,
`make_demo_extra.py`), start `web/server.py` with `MOVIE_BUFF_MOCK=1 PORT=8765`, seed with `tools/seed_demo.py`, then
`node tools/accept_redesign.js` (needs `axe-core` and `@fontsource/inter` in `tools/node_modules`).

## 5. How features are judged
Rule first, then the run: each switch has a pass rule written before its first result (validation matrix,
`docs/validation_matrix.md`; decisions in `docs/decision_log.md`, newest first, with "rule written before results?").
Tuning sets may be reused; sealed sets are run once by `run_final_v8.sh` (arms v7, v8, and v8 minus each new switch),
scored by the eval_v3 judge AND judge-free checks (`final_score.py`, `judge_audit.py`, `tools/long_eval.py`).

## 6. Prediction model (box office, pf1-pf5)
- Target: log(worldwide gross / budget) (0 = earned its budget back; `performance.py`); trained on films <= 2015, tested on 2016-2019, 2020-23 reported.
- pf4 "before release + trailers": test MAE 1.200 (the reference).
- pf5 (9 Nov, `pf5_data.py`, `pf5_model.py`): A people in the news, C economy + genre momentum, D track records,
  each vs pf4 with a bootstrap 95% CI. None passed: A -0.002 [-0.008, +0.005], C +0.001 (planned version, not
  blind), D -0.006 [-0.016, +0.004]; shuffled control +0.011. **Answer: no gain from these groups.**
- B (Guardian articles before release): only 572 / 8,742 training films fetched (500 calls a day). Nightly now fetches
  ~400 a night (round 27), about 20 nights to finish; then B gets its own train <= 2015 / test 2016-19 run.
- 80% ranges: conformalized quantile regression, test coverage 78.1% (calibrated, 75-85% rule) - reported only.
- The model is not shown on the site (PERF=0).

## 7. Website features (v8)
Home (rows, genre chips Any/All, TV rows), Ask Cinemack (streaming chat, filter bar shared with Home, Any/All
genres from round 27, private chat, 3c chips, saved chats), Pick Tonight (films or TV; hard limits in code),
Calendar (week / month; theatrical, digital, TV seasons, episodes of followed shows, finales; TVmaze air times in the
viewer's time zone from round 27), film and show pages (show page: TVmaze schedule line "Sundays at 9:00 pm ET on
AMC", episode summaries from TVmaze where TMDB has none), Watchlist (films + TV progress, alerts in the bell),
Profile (stats, imports from Netflix / Letterboxd / Trakt, friends, privacy, custom banner upload from round 27,
"Chat and memory" settings with notes and chat cards, email digest of alerts), create-account flow `#/join`.

Not done, and why: HTTPS (ports 80/443 belong to another service on the server); push notifications (the browser
Push API needs HTTPS); real showtimes (no authorised theatre API: links are labelled searches); "leaving streaming"
dates (no source). Email alerts run in a sandbox until SMTP details are added to keys.env (EMAIL_SANDBOX=0).

## 7b. Search embedder fine-tuning (shadow only)
`tools/embed_ft.py`: training queries are the generated tip-of-the-tongue descriptions (wiki.db gen_questions), films
named in any question set are left out, hard negatives come from the base model; only the top 8 layers train. It is
measured on a shadow index (numpy) against the same base model; the live search still uses Ollama's mxbai until the
fine-tuned model passes its gate and is converted for Ollama.
